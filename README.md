# tokenvalidator

离线委任令牌验证器（Go CLI）。不连接任何身份服务，仅根据信任根公钥、委任令牌批次和撤销列表，判断某主体能否在指定整数时刻对某资源执行某动作。主体与签发者均以 Ed25519 公钥标识。

## 构建与运行

```sh
go build -o validator .
./validator input.json        # 或省略文件名，从 stdin 读取
```

退出码：`0` 已授权，`1` 未授权，`2` 批次被拒绝 / 输入非法。结果 JSON 打到 stdout。

## 输入格式

```json
{
  "roots":   ["<base64 ed25519 公钥>"],               // 1～4 个信任根
  "tokens":  [                                        // 最多 40 个委任令牌
    {
      "id": "t1",
      "issuer":    "<base64 公钥>",
      "subject":   "<base64 公钥>",
      "actions":   ["read", "write"],
      "path":      "/docs/",
      "not_before": 100,
      "not_after":  200,
      "depth":      2,
      "signature": "<base64 签名>"
    }
  ],
  "revoked": ["t9"],                                  // 撤销的令牌 ID（未知 ID 忽略）
  "request": { "subject": "<base64 公钥>", "action": "read",
               "resource": "/docs/team/a.txt", "time": 150 }
}
```

## 规则

**签名载荷**：`id、issuer、subject、actions（排序去重）、path、not_before、not_after、depth` 全部字段按长度前缀编码（每字段 = 8 字节大端长度 + 字节串；整数为 8 字节大端；动作集合先写个数再逐个写），Ed25519 签名覆盖该完整字节串。签名覆盖的是**原始** `path` 字段；下文的路径规范化身份由该已签字段确定性导出，改写原始字段（即使改写为等价拼写）都会使签名失效。

**路径规范化**：做任何匹配之前，令牌路径与请求资源都先规范化为段序列——忽略空段（前导、结尾或重复分隔符）与 `.` 段；`..` 弹出上一段（根部的 `..` 直接丢弃，路径不会升到根之上）。收窄判断、请求匹配、撤销与有效期检查所作用的链、以及输出的逐层证据，全部基于该规范化身份：等价拼写得到相同结论，`..` 无法逃逸已授权的前缀。

**整批拒绝（fail-closed，退出码 2）**：令牌数量超限、重复令牌 ID、任何令牌签名无效、签发者既非信任根也不是批内任何令牌的主体、委任图存在环（含自委任）、字段畸形（负层数、空有效期等）。

**有效链**：从某信任根签发的令牌出发，每条边 `父 → 子` 满足
- 子的签发者 == 父的接收者；
- 子的动作集合 ⊆ 父的动作集合；
- 子的路径前缀在父前缀之下（按规范化后的 `/` 段边界匹配：`/a/b` 下含 `/a/b/c`，不含 `/a/bc`）；
- 子的有效期 ⊆ 父的有效期（半开区间 `[not_before, not_after)`）；
- 子的剩余委任层数严格小于父的；
- 链上所有令牌均未被撤销。

链尾令牌的主体即请求主体，且请求动作 ∈ 链尾动作集、规范化后的资源位于链尾路径前缀下、时刻落在链尾有效期内（由收窄关系可知对全链成立）。

**输出**：存在多条有效链时，返回令牌 ID 序列字典序最小的一条，并附逐层收窄证据（`evidence[].narrowing`）；否则返回 `status: "unauthorized"` 及逐候选失败原因。证据中 `path` 为已签原始字段、`canonical_path` 为实际判定所用的规范化身份；`request_check` 同样给出 `resource` 与 `canonical_resource`，保证输出与最终被判定的资源身份一致。

## 测试

```sh
go test ./...
```

测试使用 `ed25519.GenerateKey` 生成真实密钥，覆盖：改动签名载荷（逐字段篡改）、边界时刻（`not_before` 含、`not_after` 不含）、近似路径（`/a/bc` vs `/a/b`）、路径规范化（`.`、`..`、重复分隔符的等价拼写结论一致，`..` 逃逸前缀被拒绝，令牌路径按规范化身份收窄，签名绑定原始 `path` 字段，证据与 `request_check` 输出规范化身份）、中途撤销（根/中间/叶子）、字典序选链、层数不下降、动作/时间扩权、委任环、重复 ID、未知签发者、批次上限，以及 CLI 端到端退出码。
